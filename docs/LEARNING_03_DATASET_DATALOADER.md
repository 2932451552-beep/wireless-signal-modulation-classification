# 第三课：PyTorch Dataset 与 DataLoader

## 1. Dataset是什么

`Dataset`可以理解为仓库管理员。它知道：

- 一共有多少条信号；
- 根据编号如何取出一条信号；
- 这条信号对应哪个调制标签；
- 这条信号处于什么SNR条件。

本项目取出一条样本时返回：

```text
signal：形状(2, L)的I/Q信号
label：调制类别编号
snr：信号的SNR
```

## 2. DataLoader是什么

`DataLoader`可以理解为送货车。它从Dataset中取出多条样本，组成一个批次送给模型。

如果`batch_size=32`、每条信号长度为128，批次形状是：

```text
signal：(32, 2, 128)
label：(32,)
snr：(32,)
```

模型主要读取signal并预测label；snr用于后续分组评估，不是模型必须预测的答案。

## 3. 为什么使用批次

模型通常不会一次只处理一条信号，也不会一次把全部数据塞进显存。批次是在训练速度和内存占用之间进行平衡：

- 批次太小：一次处理的数据少，训练可能较慢、梯度波动较大。
- 批次太大：需要更多显存，可能直接出现显存不足。

第一版会从较保守的批次大小开始，再根据RTX 4060的8GB显存实测调整。

## 4. Shuffle的作用

训练集通常启用`shuffle=True`，每轮改变样本顺序，避免模型持续按照固定类别顺序学习。验证集和测试集通常不需要打乱，因为它们不更新模型参数。

DataLoader也使用固定随机种子，使相同实验能够产生相同的初始批次顺序。

## 5. CPU和GPU分别做什么

Dataset和DataLoader先在CPU中读取、检查和组装数据。训练循环再把当前批次移动到GPU：

```text
磁盘/内存 → Dataset → DataLoader批次 → GPU → 模型
```

不要在Dataset内部提前把全部数据放进GPU，否则数据量变大后会快速占满显存。

## 6. 当前Windows设置

第一版使用`num_workers=0`，先保证Windows环境稳定。后续只有在数据读取成为瓶颈并完成测试后，才增加并行工作进程。

本课只验证数据进入PyTorch的链路，不训练CNN，也不产生准确率。
