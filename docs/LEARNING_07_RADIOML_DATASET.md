# 学习 07：RadioML 2016.10A 真实结构

## 数据从哪里来

本项目使用从 DeepSig 官方页面申请并通过邮件下载的 `RML2016.10a.tar.bz2`。它是 GNU Radio 生成的历史合成基准数据，不是真实空口采集数据。

许可证为 `CC BY-NC-SA 4.0`：使用时需要署名，只能用于非商业目的；如果公开改编数据，还需要遵守相同许可。原始数据和解压文件都不能提交到 GitHub。

- 压缩包大小：228,491,318 字节
- 压缩包 SHA-256：`7a1603dd61e557f45b6e113dc0c59be02a14509b77856c31bbb324a993f7974c`
- Pickle 大小：640,919,653 字节
- Pickle SHA-256：`b29ccc25b00d0718cd3b70ffa9158662ec83f6d9b63ffd845c7bcbe3b3096e8c`
- 调制类别：11种
- SNR档位：20个，从 -20 dB 到 18 dB，间隔2 dB
- 分组数：11 × 20 = 220组
- 每组：1000条信号
- 总样本：220,000条
- 单条信号：2个I/Q通道，每个通道128个采样点
- 数据类型：`float32`
- 有限值检查：通过，没有NaN或无穷值

11种调制方式为：

```text
8PSK, AM-DSB, AM-SSB, BPSK, CPFSK, GFSK,
PAM4, QAM16, QAM64, QPSK, WBFM
```

## 为什么不能直接 pickle.load

Pickle不只是数据格式，也能记录Python对象的构造方式，因此来源不明的Pickle可能执行危险代码。本项目先完成压缩包路径检查和Pickle指令扫描，再使用只允许NumPy数组构造器的受限读取器加载；任何其他全局对象都会被拒绝。

这种流程只能降低风险，不能证明任意Pickle绝对安全。这里能够继续读取，还依赖于文件来自官方邮件链接、哈希已记录、内部对象与公开数据结构一致。
